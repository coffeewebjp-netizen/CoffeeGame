# First Combat Slice

## 目的

少女がスライムを倒す最小戦闘をブラウザで試し、Unityへ移す戦闘仕様を決める。ブラウザ版を製品化することが目的ではない。

最終ターゲットは Unity 6 + C# + URP で作る Windows / Android アプリ。Googleアカウント同期とCoffeeLearning連携は、そのアプリから共通バックエンドへ接続する。

## 今回のプレイ範囲

```text
開始
  ↓
スライム出現 → 戦闘 → 撃破
                         ↓
                  報酬を一度だけ加算
                   ├─ 5体未満: 次のスライム
                   └─ 5体撃破: 結果画面
```

- 主人公1人、スライム1種類
- 同時に出現する敵は1体
- 移動、ジャンプ、空中斬り、急降下突き、剣、必殺、魔法
- 3体目で最初のレベルアップ
- 5体目で試遊終了

## 初期パラメーター

| 項目 | 値 |
| --- | ---: |
| 主人公HP | 24 |
| 主人公MP | 12 |
| 移動速度 | 歩き155、同方向0.65秒後に走り245 |
| 剣 | 威力3、間隔0.34秒、命中時ST+25 |
| ジャンプ | 初速480、重力1180、空中の移動倍率72% |
| 空中なで斬り | 1ジャンプ1回、威力4、範囲94、命中時ST+25 |
| 急降下突き | 空中で下入力、威力8、衝撃波範囲118、着地硬直0.48秒 |
| 回転斬り | 0.8秒チャージ、威力12、360度・範囲142、ST100消費 |
| 氷魔法 | 0.65秒チャージ、威力5、MP4消費、MP毎秒0.45回復 |
| スライム | HP12、攻撃2、攻撃間隔2.4秒、予兆0.55秒 |
| 撃破報酬 | EXP1、Gold1、スライムゼリー1 |
| Lv1→2 | EXP3 |
| レベルアップ | 最大HP+4、最大MP+2、剣威力+1、HP/MP全回復 |
| 試遊終了 | 5体撃破 |

## 報酬の不変条件

1体のスライムから受け取れるのは、EXP 1、Gold 1、スライムゼリー 1だけとする。敵に一意なIDと `rewardApplied` を持たせ、連打、複数ヒット、撃破演出中の入力で二重付与しない。

敵ドロップのGoldとCoffeeLearning由来の共有ポイントは、現段階では別残高にする。倍率と価値が違うため、経済設計が決まる前に統合しない。

## 入力アクション

ブラウザのキー番号やUnityのデバイスを戦闘処理へ直接結びつけず、次の論理アクションへ集約する。

| アクション | キーボード | Steam Controller / Standard Gamepad |
| --- | --- | --- |
| `Move` | WASD / 矢印 | 左パッド・Stick / D-pad |
| `Jump` | Space | A |
| `Sword` | F | RT（空中ではなで斬り） |
| `Plunge` | 空中でS / 下 | 空中で左パッド・D-pad下 |
| `Special` | Q | X |
| `Magic` | E | Y |
| `Confirm` | Enter / R | A / Menu・Start |

Web版はStandard Gamepad mappingだけを安全な割り当てとして扱う。非標準mappingは誤操作を避けるため停止し、Steam InputのGamepadテンプレートまたはLegacyキーボード割り当てへ誘導する。Unity移植時はUnity Input Systemから同じアクションへ渡し、Steam版で必要になった段階でSteam Inputの`Battle` / `Menu` action setへ接続する。

Steam Input Legacyはブラウザから通常のキーボード／マウス入力に見えるため、機器の接続有無は断定しない。操作を検出した場合は`KEY / Legacy`と表示する。ジャンプ・剣・必殺・魔法・決定のPAD/Legacy割り当てはゲーム内で変更でき、ブラウザではlocalStorageへ保存する。Unity移植時は同じ設定を端末設定またはクラウド設定へ移す。Aは戦闘中の`Jump`と、待機・結果画面の`Confirm`で文脈的に共有する。

## 状態の境界

将来の保存データは次の二層に分ける。

| 層 | 例 | 保存先の将来像 |
| --- | --- | --- |
| Profile | レベル、累計EXP、通貨、素材、装備 | Googleアカウントに紐づくクラウド |
| Run | HP、MP、ST、座標、現在の敵 | 原則その端末、必要なら中断データ |

今回のブラウザ試遊では永続保存しない。調整中の古いデータが評価を歪めないよう、再読込で初期状態に戻す。

## 試遊と調整の進め方

1周15～45秒程度を目安に数回繰り返し、合計2～3分触って次の順に判断する。開始ボタンを押すまでは戦闘と計測を始めず、調整パネルを開いている間も一時停止する。

1. 剣の入力反応と連打間隔
2. ジャンプ高度、空中斬り、急降下と着地硬直
3. スライムの硬さと攻撃圧
4. 必殺が溜まるまでの長さと爽快感
5. 魔法の威力、MP消費、回復速度
6. 報酬とレベルアップが読み取れるか
7. PCとスマホ幅でボタンが押しやすいか

一度の変更は2～3項目までにし、良くなった原因を追えるようにする。画面の調整パネルで変更し、採用値だけをこの文書へ反映する。

## 受入条件

- 剣入力に即座に斬撃表示が返る
- A / Spaceでジャンプし、一定時間後に地面へ戻る
- 空中の剣入力は1ジャンプ1回のなで斬りになり、方向別画像が切り替わる
- 空中の新しい下入力で急降下し、着地時に範囲ダメージと0.48秒の操作不能が発生する
- 剣4命中でSTが100になり、回転斬りは0.8秒後に360度へ1回だけ命中する
- 氷魔法はMPが4減り、0.65秒後に氷晶弾が1発だけ生成される
- スライム1体につき各報酬が厳密に1だけ増える
- 3体撃破でLv1からLv2になる
- 5体撃破時にGold 5、ゼリー5で結果画面へ進む
- マウス、キーボード、タッチ想定の画面ボタンで一周できる
- 390px幅でも操作UIが重ならない
- 複数周、合計2分間の試遊でコンソールエラーが出ない

## Unityへ移す条件

上の7つの手触り項目に大きな違和感がなく、採用パラメーターがこの文書に固定された時点でUnity実装へ進む。移植時はブラウザの描画コードを再利用せず、仕様、入力マッピング、報酬ルール、調整数値をC#のデータとして再構築する。

Unity移植後、早い段階でWindowsビルドとAndroid実機起動を確認する。CoffeeLearning連携は `ILearningBridge` 相当の境界を設け、戦闘ロジックからAPIを直接呼ばない。
