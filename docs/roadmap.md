# Roadmap

## 目的

このロードマップは、`docs/concept.md` のゴールを実装順に落とすための計画です。

最初の到達点は、Unityで作る 2.5D 見下ろしアクションRPGの縦スライスです。Webプロトタイプは補助として使いますが、制作の本流は Unity に置きます。

## 現在のゴール

PCで遊べる小さな縦スライスを作り、Androidでも起動確認する。

縦スライスの完了条件:

- プレイヤーを動かせる
- 通常攻撃が出せる
- 回避できる
- スキルを1つ使える
- 敵3種類が出る
- 小ボスが出る
- 敵を倒せる
- HPが増減する
- ドロップを拾える
- 簡単な成長がある
- 短い導入がある
- タイトルからゲームを開始できる
- PCビルドを作れる
- Androidで起動確認できる

## フェーズ0: 企画の固定

目的: 作るもの、作らないもの、判断基準を固定する。

作業:

- コンセプトを整理する

- 本命エンジンを Unity に決める
- Webプロトタイプの役割を補助に限定する
- 最初に入れない要素を明文化する

完了条件:

- `docs/concept.md` が制作判断に使える状態になっている
- `docs/roadmap.md` が実行順を示している

状態: 完了

目的: Unityに入る前に、少女対スライムの移動、剣、必殺、魔法、撃破報酬の気持ちよさを小さく確認する。

使うもの:

- `haxslasher/index.html`

作業:

- 移動速度と剣の範囲・テンポを調整する
- ST100で使う必殺技の溜まり方と威力を調整する
- MPを消費する魔法の威力・消費・回復を調整する
- スライムのHP、攻撃力、攻撃間隔を調整する
- EXP1、Gold1、スライムゼリー1の見え方を確認する
- 3体目のレベルアップと5体討伐結果を確認する
- PC操作とAndroid横画面想定の画面ボタンを確認する

完了条件:

- 30～60秒触って、剣・必殺・魔法の役割がわかる
- 敵1体から各報酬が一度だけ増える
- 採用する調整数値が `docs/first-combat-slice.md` に固定される
- WindowsとAndroidへ移す操作仕様を説明できる

成果物:

- Webプロトタイプ
- `docs/first-combat-slice.md`（Unity移植用の仕様メモ）

状態: 実装済み、ユーザー試遊と数値調整待ち

## 横断フェーズA: CoffeeLearning連携の土台

目的: 学習機能を大量に作る前に、アカウント連携と共有データの境界を固定する。

早期に行う作業:

- `docs/coffeelearning-integration.md` のデータ契約を確認する
- Unity側に `ILearningBridge` と `MockLearningBridge` を用意する
- schema version付きのstudy pack、回答、当日ポイント、受取証DTOを決める
- 全既存デッキを`deckKind`へ分類し、新規デッキにも分類を必須化する
- Game→Learning用`challengeKinds`とLearning→Game用`earningEventKinds`・`pointPolicyId`を分ける
- CoffeeLearningとのブラウザ往復認証をWindowsで検証する
- Android用App Linkまたは専用URIの戻り導線を検証する
- CoffeeLearningの弱点スコアをバックエンド共通関数へ移す方針を決める
- study packは汎用を含む単語系弱点だけに限定する
- 当日ポイントは全学習デッキを対象にする
- 単語ポイントは1倍、英語日記・抽象思考の正規評価点は100倍とするサーバー換算規則を決める
- 学習完了ごとの不変なポイント獲得イベントを設計する
- 日本時間の当日獲得額、発行済み額、受取可能差分を持つ日次台帳を設計する
- 単語系の弱点情報と全デッキの当日ポイントを必要最小限だけ返すbootstrap APIを設計する
- 同じ回答、日記・ワーク保存、受取を再送しても一度だけ処理する冪等キーを決める

早期完了条件:

- CoffeeLearningが停止中でもゲームを起動して遊べる
- mockデータをゲーム画面へ渡せる
- WindowsとAndroidの認証コールバック方式が決まっている
- CoffeeLearningとCoffeeGAMEが互いのDBを直接更新しない契約になっている
- 単語系だけをゲームから更新でき、非単語デッキは現在拒否される契約になっている
- 英語日記と抽象思考は生成時の正規評価点が100倍になり、再保存では増えない
- ゲームでの単語クリアがLearningの`ok`とゲーム通貨へ同じUXフローで反映される
- 累計ポイントを配り直さず、その日の新規獲得差分だけを受け取る契約になっている
- 複数端末から同時に受け取っても、同じ`claimId`が二重適用されない

デッキ分類、ポイント台帳、受取契約は早期に固める。実際の「記憶の祠」、回答同期、通貨の使用先は、戦闘とドロップの基礎ができた後に実装する。連続石交換は今回の境界外に置く。

## 保留リスト

縦スライスが面白くなるまで入れないもの:

- 広大な3Dフィールド
- 仲間切り替え
- マルチプレイ
- ガチャ
- 大量のクエスト
- 豪華な街
- ボイス
- 本格3Dモデル
- 複雑な属性システム
- 大規模なストーリー分岐

## 次にやること

1. Steam ControllerでA／RT／X／Yの最終配置と再割当を試遊確認する
2. HD-2Dの顔、頭身、アクション間の統一と戦闘フィードバックを調整する
3. Android Build Support、Android SDK & NDK Tools、OpenJDKを導入する
4. Android開発APKをビルドし、横画面、タッチUI、音声、復帰動作を確認する
5. 操作レビュー後に回避、ヒットストップ、カメラ揺れをUnity側へ追加する
6. CoffeeLearning連携のローカルモック、Profile save、Google認証導線へ進む

最新の検証結果と未完了項目は `docs/current-status.md` を参照する。

Web版は比較用に残し、以後の肉付けはUnity側で行う。この順番を守り、面白さの芯が固まるまで機能を広げすぎない。
